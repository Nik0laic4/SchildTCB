## 1. Назначение и область применения

Schild TCB — приватный научно-исследовательский прототип доверенной
вычислительной базы (Trusted Computing Base) и среды изолированной периферии,
реализованный на языке Ada/SPARK 2022 (с элементами C и ASM) поверх
прекомпилированного микроядра seL4 для архитектуры Intel x86_64 (режим
Long Mode, SMP).

Прототип предназначен для научно-исследовательских и учебно-образовательных
целей: отработки формальной верификации ядра (SPARK), моделей мандатного
управления доступом (MLS Bell-LaPadula) и изоляции некритичной периферии
(сетевой стек, драйверы NVMe/e1000e) в защитные домены микроядра.

Ключевые характеристики текущей версии:

- **Формальная верификация.** 183 модуля ядра входят в набор доказательства и
  обрабатываются на 4-м уровне строгости SPARK (gnatprove `--level=4
  --mode=all`, скрипт `scripts/prove_kernel.sh`); результат — 0 непроверенных
  проверочных условий (`not-proved: 0`). Дополнительно 4 демона root-задачи
  (политика MLS, конфигурационный демон, журнал аудита, загрузчик A/B)
  доказываются в составе `verify.gpr`.
- **Сборка без ошибок.** 179 объектов Ada + C + ASM, 0 ошибок (`./build.sh`).
- **Загрузка с физического носителя.** Образ загружается с USB-флеш-накопителя
  (проверено на ThinkPad T580) и в эмуляторе QEMU; в состав входит
  функционирующий сетевой стек (ARP / IPv4 / ICMP / TCP / HTTP).

## 2. Технические характеристики и архитектура

### 2.1. Слои ядра

| Слой | Назначение |
|------|-----------|
| `01_hardware` | Управление оборудованием: MMU, APIC/IOAPIC, NVMe, e1000e, SMP, таймер PIT |
| `02_security` | MLS Bell-LaPadula, модель возможностей (cap-space), шлюз IPC, файрвол |
| `03_crypto` | AES-NI, SHA-256, HMAC-SHA256 (FIPS 198-1), генератор случайных чисел |
| `04_userland` | Файловая система SchildFS/VFS, сокеты, сетевой стек (ARP/IPv4/TCP/UDP/HTTP) |

Прототип существует в двух конфигурациях:

- **Автономное ядро (bare-metal)** — загружается напрямую с носителя
  (`schild_os.iso`).
- **Интеграционный слой seL4** — root-задача Ada/SPARK и изолированные
  процессы (MLS-сервер, Config Daemon, NetServer) поверх прекомпилированного
  микроядра seL4 (`sel4_primary.iso`, артефакт для QEMU).

### 2.2. Политика мандатного доступа (MLS)

В интеграционном слое seL4 реализована модель мандатного доступа с **5
уровнями**: Public, Internal, Confidential, Secret, Top_Secret (тип
`Security_Level` модуля `Schild_Config_Daemon`, используемый политикой
`Schild_MLS_Policy`).

Автономное bare-metal ядро оперирует **4 уровнями** (подтип
`Clear_Level_Type` диапазона `1 .. 4` модуля `Schild_Mls_Core_Engine`).
Расхождение числа уровней между конфигурациями является известной
особенностью текущей версии прототипа.

### 2.3. Ограничения текущей версии (известный латентный дефект)

Для потоков MLS-сервера (слот 199) и Config Daemon (слот 526) в качестве
обработчиков сбоев (fault handler) временно используются объекты типа
Notification. Ядро seL4 в конфигурации non-MCS требует для доставки сбоя
fault-endpoint'ы, поэтому при фактическом сбое указанных потоков доставка
fault-сообщения не будет выполнена корректно. Дефект является латентным и не
проявляется в текущих тестах, поскольку данные потоки не фолтят.

### 2.4. Планировщик

Планировщик (`schild_scheduler.adb`, `schild_kernel_logic.adb`) не содержит
циклов ожидания занятости (busy-wait). Переключение задач выполняется по
честному прерыванию системного таймера PIT (канал 0, ~100 Гц, IRQ0 → вектор
0x20): обработчик выполняет EOI, вызывает `Tick()` и возвращается по `iretq`;
главный цикл ожидает следующего тика в состоянии `hlt`.

## 3. Условия выполнения и сборка

### 3.1. Требования к окружению

- Компилятор GNAT (Ada/SPARK 2022) и gprbuild; рекомендуется инструментарий
  Alire `gnat_native` 14.2.1.
- Целевая архитектура: Intel x86_64 (Long Mode, SMP).
- Для сборки загрузочного образа: grub-mkrescue (GRUB 2).
- Для прогона в эмуляции: QEMU (qemu-system-x86_64).

### 3.2. Сборка

```bash
cd src/schild_core

# Автономное ядро (bare-metal)
./build.sh

# Интеграционный слой seL4 (root-задача Ada/SPARK), для QEMU
SEL4_PRIMARY=1 ENABLE_DISTRIBUTED_LEDGER=0 ./build.sh

# Формальная верификация
bash scripts/verify.sh          # демоны root-задачи, SPARK Level 4
bash scripts/prove_kernel.sh    # полный прогон ядра (183 модуля)

# Прогон в QEMU
SKIP_BUILD=1 SEL4_PRIMARY=0 bash scripts/run_tests.sh
```

### 3.3. Генерация образа файловой системы

```bash
python3 mkschildfs.py test_disk.img
```
