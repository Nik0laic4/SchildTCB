# Каталог ошибок ИИ (case studies)

> Источник: `START/AUDIT_REGISTRY.md` (санитизировано — без внутренних деталей),
> `CHANGELOG.md`. Каждый кейс — «ювелирная работа» из аудит-реестра: что оракул
> НЕ поймал, как поймал человек, и какой урок для последователя.
>
> Формат: **контракт/состояние до → после → почему именно так → урок**.

## 1. H61 — misaligned стек (доказано ≠ работает)

- **До:** HMAC-SHA256 в FS-демоне **доказан** (SPARK Level 4). Но демон висел молча.
- **Что НЕ поймал оракул:** выравнивание стека — вне модели SPARK. Стек FS-демона
  оказался смещён на 8 байт, `movaps`/`movdqa` (aligned SSE в SHA256) дал `#GP` →
  тихий hang. Тесты не ловят (hang молчаливый).
- **Как поймал человек:** система маркеров `run_tests.sh` + бинарный поиск.
- **После:** `andq $-16, %rsp` в `fs_daemon.S`.
- **Урок:** оракул доказывает *логику*; *среду исполнения* (стек, выравнивание,
  тайминги, железо) он не видит. Нужны оба — доказательство (внутри модели) и
  маркеры/тесты (вне модели).

## 2. W11.1 / M3 — вакуумный Post (прошёл все гейты)

- **До:** `schild_audit_chainer` имел `Post => (Is_Chain_Valid = constant True)` —
  тавтологию.
- **Что НЕ поймал оракул:** gnatprove ловит **недостижимый `Pre`**, но **не
  тавтологичный `Post`**. Все гейты были зелёные.
- **Как поймал человек:** ручное ревью контрактов (это в правилах — вакуумность
  ловится только ревью).
- **После:** `Post` переписан на фактическое security-свойство цепочки.
- **Урок:** `not-proved: 0` ≠ «контракты содержательны». Тавтологичный Post —
  это единственный класс вакуумности, который инструмент пропускает; он обязан
  быть в чек-листе ревью.

## 3. C23 — Pre не enforced у Off-caller

- **До:** HTTP-обработчик `Handle_Request` (`schild_http_server.adb`, Off) имел
  рантайм-guard на путь запроса (5..1024), но путь ответа был без guard — Pre
  нарушался.
- **Что НЕ поймал оракул:** SPARK доказывает для Pre-вызовов, но Off-caller не
  проверяет Pre — доказательство не переносится на Off-вызов.
- **Как поймал человек:** аудит (C23), патч 2026-11-03.
- **После:** guard добавлен в `Handle_Request` (заниженный `Reply_Buf` → `Success=False`
  без OOB).
- **Урок:** любой `SPARK_Mode => Off` вызывающий Pre-контрактный код — это точка,
  где доказательство «не доезжает»; нужен runtime guard на месте вызова.

## 4. M1 — PID reuse (CVE-2026-SCHILD-02 #005)

- **До:** PID переиспользовался немедленно при завершении (без окна охлаждения);
  signal/IPC для только что завершённого процесса мог достичь несвязанного
  преемника.
- **Что НЕ поймал оракул:** это свойство *времени жизни идентификаторов*, а не
  memory-safety — вне модели SPARK. Нашёл аудит модели угроз, не прувер.
- **После:** монотонная генерация PID на слот (`PID = Slot + Generation ×
  Max_Processes`) закрывает немедленное переиспользование.
- **Урок:** security-свойства шире, чем отсутствие runtime-ошибок. Модель угроз —
  отдельный от доказательства источник находок.

## 5. H82 — Persist silent fail (`not-proved: 0` ≠ работает)

- **До:** `Persist_Audit_Log` проходил пруф, но NVMe `Is_Ready=False` — Init
  выходил молча, аудит-лог не персистился.
- **Что НЕ поймал оракул:** корректность *I/O-устройства* вне модели; контракт
  доказан, а устройство не готово.
- **Как поймал человек:** порядок инициализации (Stage 7.2 vs 8.1D) + маркер.
- **Урок:** «доказано» — про *логику модуля*, не про «устройство реально работает».
  Liveness/I-O проверяется тестами, не доказательством.

## 6. H67 — два списка сборки (класс «модуль в одном списке, не в другом»)

- **До:** `build_rt.sh` имел ДВА списка (compile `for spec` + link `.o`). Новый
  модуль добавлялся в один — SEL4_PRIMARY ломался.
- **Что НЕ поймал оракул:** это не контракт, а процесс сборки — вне SPARK.
- **Как поймал человек:** `check_build_lists.sh` (fail-fast в CI).
- **Урок:** класс механических дрейфов (списки, числа, маркеры) ловится скриптами,
  а не доказательством. CI-гейт `check_build_lists.sh` — часть конвейера.

## 7. AS8 — патчи на доказанное ядро (что значит «reviewed, не re-proven»)

- **До:** seL4 — machine-checked функционально-корректное ядро (сильнейшее для
  ARM-конфигурации). Понадобилось 7 локальных патчей (SMAP, object-zeroing,
  framebuffer ×3, bootinfo-8k, max-num-drhu, load-image).
- **Что НЕ поймал оракул:** каждый патч меняет доказанное ядро, но **не
  пере-доказывается** — апстрим-гарантия переносится лишь частично. Это
  ослабление «по дизайну», признанное явно (AS8).
- **Как держится под контролем:** per-patch ревью + классификация рисков +
  стратегия минимизации (root task как ELF-child снимает часть патчей,
  Kconfig-миграция, апстрим-обновления) — `SEL4_PATCHES_ANALYSIS.md`.
- **Урок:** патчить доказанный компонент — осознанный trade-off, который надо
  фиксировать как residual, а не прятать. Минимизация патчей — часть роадмапа,
  а не «потом».

## Общий паттерн

| Класс ошибки | Ловит | Не ловит |
|---|---|---|
| Memory-safety / диапазоны / переполнение | gnatprove (Level 4) | — |
| Тавтологичный Post (вакуумность) | — (только ревью) | gnatprove |
| Pre у Off-caller | — (runtime guard) | gnatprove |
| Выравнивание стека / среда исполнения | маркеры `run_tests` | gnatprove |
| I/O-готовность / liveness | тесты + маркеры | gnatprove |
| Дрейф списков/чисел | скрипты (`check_build_lists`, `check_metrics`) | gnatprove |

**Вывод:** оракул покрывает *одну* ось (формальную корректность внутри модели).
Всё остальное закрывается эшелонированно: ревью (вакуумность), runtime-guard
(Pre у Off), маркеры (среда), скрипты (дрейф). Это и есть архитектура конвейера.
