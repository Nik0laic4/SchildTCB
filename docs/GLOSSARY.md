# Глоссарий Schild TCB

> Термины, без которых не читаются `docs/technical/` и `docs/methodology/`.
> Порядок — от «что такое доказательство» к «как устроен TCB».

## Формальная верификация (SPARK)

| Термин | Что значит |
|---|---|
| **VC** (Verification Condition) | Условие верификации — элементарная цель, которую gnatprove должен доказать (например, «индекс массива в границах»). «390/390 proved» = все 390 целей доказаны. |
| **Pre / Post** | Пред-/постусловие подпрограммы. `Pre` — что должно быть истинно на входе, `Post` — что гарантируется на выходе. Контракт. |
| **Proved / Unproved** | Вердикт gnatprove по VC. `not-proved: 0` = ни одной недоказанной. `medium:`/`high:` в выводе = **недоказанные** VC (гейт ловит их). |
| **Vacuity (вакуум)** | Контракт, истинный «в пустую» (например, `Pre => False` или `Post => True`). gnatprove ловит недостижимый `Pre`, но **не** тавтологичный `Post` — это ловит только ревью. |
| **Level 4** | Максимальный режим gnatprove: доказывает отсутствие runtime-ошибок (деление на 0, OOB, переполнение, разыменование null) для SPARK_Mode => On кода. |
| **SPARK_Mode => On / Off** | `On` — тело подлежит доказательству; `Off` — тело трактуется как «доверенное» (seL4-механизм, I/O), вне модели доказательства. |

## Архитектура TCB

| Термин | Что значит |
|---|---|
| **TCB** (Trusted Computing Base) | Минимальный набор компонентов, отказ которых компрометирует всю систему. Цель — сделать его маленьким и доказуемым. |
| **Tier A / B / C** | Разделение по доверию. **Tier A** — ядро TCB (syscall-шов, root task, boot manager, MLS policy, FS server): любая правка требует escalation. **Tier B** — изолированные драйверы (NetServer и т.п.). **Tier C** — доверенный Off-код. |
| **Capability (cap)** | Непередаваемый токен доступа к объекту ядра (endpoint, frame, TCB, untyped). В CSpace процессы держат только те cap'ы, которые им выданы — изоляция на уровне ядра. |
| **CSpace** | Пространство capability-слотов процесса. root task раздаёт daemon'ам их CNode/cap'ы; без cap'а в своём CSpace процесс не может Signal/Send. |
| **Untyped** | Capability на неинициализированную физическую память; через `Retype_Object` из него «вырезают» объекты ядра (frames, endpoints, TCB). |
| **Endpoint (EP) / Notification (ntfn)** | Примитивы IPC seL4: EP — синхронный Send/Recv, ntfn — асинхронный signal (с badge-битами). |
| **Ring 3** | Непривилегированный режим CPU, где работают изолированные драйверы (NetServer, FS); изоляция через seL4, не через MMU-доверие к коду. |

## Процесс (методология)

| Термин | Что значит |
|---|---|
| **Бинарная граница (Tier A allowlist)** | Граница по **имени файла**, не по «важности». Файл из allowlist → escalation всегда, даже «одна строка». |
| **Escalation** | Стоп и вопрос человеку (не решать самому). Список из 12 случаев в `docs/methodology/README.md` §2/§4. |
| **Gate** | Проверка перед коммитом (build / verify / private / run_tests / check_build_lists). Упал гейт → нет коммита. |
| **Оракул (gnatprove)** | Безразличный проверяющий в конце конвейера: человек задаёт правила, ИИ генерирует, оракул доказывает. |

## Прочее

| Термин | Что значит |
|---|---|
| **MCS** | Mixed-Criticality Scheduling — конфигурация seL4 с механизмами реального времени. |
| **H- / M- / R- / AS-** | Идентификаторы задач аудит-реестра: H — hardening, M — методология, R — residual, AS — assurance. |
| **residual (резидуал)** | Принятый осознанный остаточный риск, задокументированный в `ASSURANCE.md` §9 (не скрытый дефект). |
